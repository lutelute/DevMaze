## 鉄則・地雷

- **実測せずに「◯px空いている」と言わない。** fableの統合案は「6行で約500px空→80%台」と
  書いたが、実測すると 71%→74% の +3pt だった。行の高さは 178→138 に減ったのに、
  空いたぶんを**折り返し最適化が「行を1本増やす」方に使った**（6行→7行、総高 1068→1046 で横ばい）。
  伸びたのは行幅が 1334→1144 と画面比に近づいたぶんだけ。
- **この画面の理論上限は約84%**（キャンバス1148×856=98万px² ÷ 中身1322×1046=138万px² の平方根）。
  詰め方で取れるのは残り10ptまで。それ以上は「中身を減らす」か「面を増やす」しかない。
- **倍率を測るときは条件をそろえる。** リモート新着バナー(36px)が5分ごとに再表示され、
  詳細パネル(280px)の開閉でも変わる。`location.reload()` → バナー✕ → 測定 の順で毎回リセットすること。
  これを怠って 59% / 69% / 71% / 73% / 74% とバラバラの数字を出して比較にならなかった。
- **沼マーカーは「1件でも含む」で付けてはいけない。** 102まとまり中85に付いて
  ミニマップが真っ赤になり印として死ぬ。いまは「そのまとまりの過半が沼」で66。
  AtelierXは実際にほぼ全部が沼（スコア483・超混沌）なので、二値では場所を指せない。
  DV-2の「深刻度・抜けたか・再発を帯で描き分ける」が本来の解。
- MCPブリッジ経由の codex は出力が長いと `Separator is found, but chunk is longer than limit`
  で落ちる。**Bash から codex CLI を直接叩いてファイルにリダイレクトする**（codex:codex-rescue 経由が楽）。
- claude-in-chrome は **file:// を開けない**。`python3 -m http.server` を立てて localhost 経由にする。
  ただし拡張は途中で切れることがあるので、最終的にユーザーへ見せるのは `open` コマンドが確実。
- SendUserFile は 0.5MB のPNGでタイムアウトした（30s）。画像はブラウザで開いて見せる。
- サブエージェントは完了しても本文を送ってこず idle 通知だけ来る。
  **最初から「結果をこのパスに Write しろ」と指示する**と回収が確実。

## 沼ったところ

- **行パッキングを左右対称で実装して効果ゼロだった。** `spans[row]=max(|lane|)` にしたが、
  まとまり表示では compactLanes が全非0レーンを ±1 に畳むので、どの行も span=1 になり
  高さが1pxも減らなかった。実測で「行の上76pxが空、下0px」＝**枝が下側にしか出ていない**と
  分かって、上下別々に測る方式（ups/downs）に作り直して初めて 178→138 になった。
- **CDPの計測で `document.querySelector('svg')` を使ってヘッダーのロゴSVGを拾った**。
  clientWidth が 18 で返って気づいた。`g.zoom-layer` から `ownerSVGElement` を辿ること。
- **ノードの縦の使用量を「中心間の距離」で測って「半分が空」と誤診した。** まとまりは半径が
  最大30pxあるので、半径込みで測ると 118px 使っていて、確保178pxに対する空きは60pxだった。
  最初「6行で500px空」と報告しかけたので、ユーザーに訂正した。**インクの範囲は半径込みで測る。**
- 状態を残したまま before を撮って 59% という無関係な数字を出した（詳細パネルが開いたままだった）。
